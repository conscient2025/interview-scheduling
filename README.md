# 浙江大学粤语社纳新面试排班

本仓库用精简 CSV 维护报名者、候选人排班和面试官信息，由固定脚本读取最新累计报名表、处理冲突，并在本地生成 XLSX。仓库使用私有 `main` 分支，XLSX 不上传。

> 仓库含姓名和学号，必须保持私有；仅限纳新管理人员访问。

## 功能概览

- 按学号合并累计报名数据，同一人重复提交时采用最新记录。
- 在报名者明确选择的线下时间内自动排班，并尽量保留已有有效安排。
- 自动减少 1～2 人场次，目标每场 5 人，必要时允许 6 人。
- 每次运行先读取现有排班 XLSX 的手填面试官栏，并将其作为最新记录。
- 生成本地排班表、预览图和冲突报告。
- 校验通过后直接更新 GitHub `main`；不使用 PR，也不 force push。

## 2026 年场次

每场 30 分钟，场次间隔 10 分钟，共 41 场。

| 日期 | 可用时段及起始时间 |
| --- | --- |
| 9 月 27 日 | 上午 10:00、10:40、11:20；下午 14:00、14:40、15:20、16:00、16:40；晚上 19:00、19:40、20:20、21:00、21:40 |
| 9 月 28～30 日 | 每晚 19:00、19:40、20:20、21:00、21:40 |
| 10 月 7 日 | 与 9 月 27 日相同，全天均为线下面试 |

XLSX 保留社长层、教育部、统战部、纵横部、青龙部、表演部六个面试官栏。面试官由管理层手填；下次运行会先导入这些单元格的文本，再重新生成排班表。格式和地点不在本功能的维护范围内。

## 排班规则

规则按以下优先级执行，前项优先于后项：

1. 每名报名者只安排一次，且必须在本人选择的具体线下时段内。
2. 尽量保留仍然有效的旧场次和座位号；发生移动时必须报告。
3. 尽可能让所有具有线下可用时间的人排上。
4. 强烈避免 1～2 人场次；目标为 5 人，3～4 人可以接受。
5. 必要时可安排 6 人并在报告中说明；自动排班绝不超过 6 人。
6. 在排班人数和分组质量相近时，先尽量不用上午，再选择较早日期。
7. 优先填满已启用场次，并尽量安排同一天的连续场次。

“国庆假期线上面试”不等于 10 月 7 日可参加线下面试。仅选择该选项者记为 `online_only`，不会自动排入 10 月 7 日。

## 数据更新方式

新 XLSX 应是包含旧记录的完整累计导出。系统只读取：`序号`、`提交答卷时间`、`1、姓名`、`3、学号`、`9、请选择你的面试时间`。

- 学号是唯一标识；问卷序号不连续不影响处理。
- 同一学号采用提交时间最新的一行；时间相同时才用序号和行位置辅助判断。
- 新导出中缺失的历史报名者会保留并报告，不会自动删除。
- 其他问卷列不进入仓库。
- 关键列缺失或出现未知时间选项时停止更新，避免错误排班。

GitHub 中的报名者数据固定为：

```csv
student_id,name,available_slots,assigned_slot,seat_no,status
```

面试官信息另存于 `data/interviewers.csv`。现有排班 XLSX 是最新来源，非空单元格会新增或更新记录，清空单元格会删除旧记录；本地 XLSX 不存在时才沿用 CSV。

## 管理层使用方法

1. 保存并关闭手工填写过的现有排班 XLSX，再导出最新的完整累计报名 XLSX。
2. 把文件的绝对路径交给已安装 `interview-scheduler` Skill 的 Codex。
3. 明确要求“生成排班并同步 GitHub main”；若只想预览，应明确说“不要推送”。
4. 查看 Agent 给出的冲突摘要和本地 XLSX，重点确认未排班、旧安排移动、1～2 人及 6 人场次。
5. 在 XLSX 中继续维护面试官；候选人变动应回到结构化数据处理，不要只改 XLSX。

推荐指令：

```text
请用 interview-scheduler 处理 D:\报名表\最新累计报名.xlsx，
生成排班和冲突总结，并同步到 GitHub main。
```

Agent 会先同步远端，再导入、排班、测试、校验和生成本地文件；推送前还会再次检查远端，发生无法安全解决的并发冲突时停止。

## 输出与异常

本地生成且不会上传 GitHub：

- `outputs/2026_interview_schedule.xlsx`：正式排班表。
- `outputs/2026_interview_schedule_preview.png`：版式预览。
- `reports/latest-conflicts.md`：面试官变化，以及候选人新增、变更、移动、未排班、仅线上、小组过小及 6 人场次。

1～2 人和 6 人场次会显著报告，但不自动阻止发布。未知字段或时间、无效座位、超过 6 人、测试失败、数据校验失败或 Git 冲突会阻止发布。

## 隐私边界

仓库只保存候选人姓名、学号、标准化可用场次、安排、座位号和状态，面试官姓名/文本，以及排班所需配置与代码。

不得提交原始/生成 XLSX、预览、报告、电话、QQ、IP、性别、专业、部门志愿、表演部兼职意向、兴趣技能、自由回答、提交时间或问卷序号。`incoming/`、`outputs/`、`reports/` 已被 Git 忽略。
